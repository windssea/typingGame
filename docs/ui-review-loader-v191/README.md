# 1.9.1 动态加载场景

## 修复与设计

旧进度条继承了 Godot 模板的 `right: 0`、`margin: 0 auto`，同时又设置 `left: 35%` 和 `width: 30%`，导致实际偏右。浏览器原生绿色进度样式也未被重置。

新版使用单列 Grid、统一的加载信息容器与明确的原生 progress 重置；进度条和百分比在同一容器内对齐。背景按 cover 等比裁切，采用明亮场景、金色标题、轻云和微光，没有增加白色弹窗。

机器人和骑士复用游戏内已生成并验收的 Grok 24 fps 动画：分别为 36 帧与 48 帧，保持原生帧序，没有补帧。仅将 PNG 图集转为带透明度的 WebP，保留 256×256 单帧尺寸。完整来源与原文件哈希见 `web/loading-assets.json`；复现命令是 `python tools/prepare-loader-assets.py`，依赖已有 ffmpeg。

两位角色可点击回应，也支持 F / J；重试按钮支持鼠标、Tab 和 Enter。预加载约 7 KB / 12 KB 的动画首帧，在完整图集抵达前先显示同一角色的静态姿态。页面遵循系统减少动态设置，隐藏时停止推进角色帧；进入游戏后注销加载层监听与动画循环。

## 真实状态

- 使用 Godot `onProgress` 提供的下载字节计算百分比，没有模拟百分比或人为等待。
- 无可计算进度时显示连接状态；下载完成但尚未启动时显示“正在启动游戏…”。
- 失败时显示中文原因并将焦点交给重试按钮，Enter 可重新加载。短横屏错误状态隐藏装饰角色，为提示和按钮留出空间。
- 游戏的 WASM/PCK、存档名称与格式不变。本次只更新 Pages 页面壳与加载资源，不重复上传 R2 游戏包。

## 验证证据

- `test-results.log`：5 项自动检查通过，覆盖重复导出、旧模板升级、R2 地址保留、不支持的模板不被覆盖，以及自定义域名 CORS 打包规则。
- `layout-validation.json`：真实浏览器读取的进度条位置，375×667、1280×720、1376×1032、1920×1080 均居中，中心误差 0 像素；另检查 768×360 横屏和错误状态。
- `preview-*.jpg` 与 `error-768x360.jpg`：使用独立本地加载夹具固定下载进度和失败状态，验证画面与键盘操作。夹具不随生产站点发布。
- `public-*.jpg` 与 `public-validation.json`：生产域名实际加载、启动及存档验证。

加载美术共 1,072,798 字节，小于旧单张 PNG 背景的 2,204,750 字节。此为文件大小对比，不代表对所有网络条件的加载时间保证。
