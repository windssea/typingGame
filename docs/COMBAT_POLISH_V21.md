# 2.1｜格斗动作与接触反馈

本轮针对实际游玩中的“火花先响、拳头后到”和角色恢复突兀进行改造。保持 2.0 的场景词牌、文字稳定锚点、空格技能和按游戏加载。

## 行为

- 输入完成即开始出拳，下一词立即可输入。伤害、声音、粒子、短暂停姿均在统一接触帧触发，不在最后一个按键触发。
- 接触时间为 4/24 秒，攻击后恢复 0.28 秒。真实 Grok 原生姿态按该战斗时钟采样，源素材保持 24fps；不生成插值帧，也不复制图像来伪造动画。
- 玩家在对手的出拳尚未接触前完成文字，可打断该拳并获得破招伤害。取消的攻击不会随后造成幽灵伤害。
- 敌人伤害和失败也等待接触；最后一拳命中后才进入胜利结算。暂停同时冻结待结算攻击。
- 两位拳手均有独立的待机、出拳、受击姿态；蓝拳准备格挡时显示真实抬臂防御姿态。引擎负责脚步推进、短促退让、粒子、光照、姿态停顿与恢复。
- 击倒时短暂清空敌方血条、淡出旧对手并恢复下一回合；继续打字可提前接上下一轮，不锁输入。
- 血条使用同题材金属框、分段渐变填充及延迟扣血层。移除遮脸的大星形贴图、浅色“漏过”提示牌及格挡圆环。

## 动画来源和审核

使用本机 Grok Build 生成四条真实视频。原片实际均为 960×960、24fps；红拳受击原片约 10.04 秒，其余约 8.04 秒。服务无法关闭原片音轨，运行资源只提取画面，打击声由游戏音效系统产生。模型名称与独立生成请求 ID 未返回时不编造，媒体文件 ID 与本地工具调用 ID 单独记录。

母版、提示词和来源详见 `ANIMATION_V21.json`。红拳母版使用内置 ImageGen，从原双人参考中提取并保留角色身份。运行图集保持 384px 单帧高清画布，统一原点，不逐帧自动裁主体。引擎导入使用 0.90 质量纹理压缩；原始 PNG 保留在仓库，动作包仅在进入格斗时加载。

蓝拳出拳源片第 19–23 个候选姿态的拳套触及画布边缘，因此不被运行资源引用。其余原生姿态组成完整的准备、伸展和恢复；没有重画缺失拳套、补帧或重复帧。蓝拳受击使用实际出现后仰的 3.375–4.75 秒区间，未采用原片误生成出拳的早期区间。候选和原始收据保留在忽略的 `build/`，不进入网页包。

## 验证

- 接触回归覆盖 30/60/120fps、接触前无伤害、命中一次、暂停、继续输入、空格格挡、破招取消、失败与最终胜利。
- 原生帧检查覆盖所有运行姿态的 384px 画布、24fps、透明边缘留白和独立攻击/防御/受击资源。
- GPU 逐帧截取出拳、受击、格挡、击倒，检查拳套与反馈实际位置；词牌不继承角色位移或震动。
- 重新导出并独立挂载 13 个小游戏的实际资源包，防止新动作导致 Web 缺依赖；线上另验真实键盘输入与存档。
