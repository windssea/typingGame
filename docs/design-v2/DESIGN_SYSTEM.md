2026-10-19 · 状态：可评审设计基线，未冻结生产标准。

**v2.1 用户反馈修订：整体UI减轻、颜色更轻松。** 默认使用明亮浅底、白色阅读面、浅蓝/薄荷/淡紫主题点缀，普通边框1dp、选中2dp、按钮深度2dp。角色与场景保留厚实体块，UI只留轻微按压感。以下旧版厚重外框描述以本次修订与`UI_LIGHTENING.md`为准；用户本次反馈优先于原提案数值。

本次交付是完整的视觉与交互重新定义，以及浏览器交互原型；不是全部美术已重制、全部 Godot 页面已替换或网页游戏已部署的声明。原型中的成绩、金币、战斗均为演示数据，不写入玩家存档。

## 1. 文档解读与本项目决策

输入文件保留原样：`five_world_design_tokens_v0.2.json` 提供 Core、五世界和起始 Tokens；`royal-fantasy-theme-kit-v1.0.md` 提供皇家专属形体、材质和边界；`theme-kit-production-template-v0.2.md` 提供生产交付与验收模板；用户粘贴的 Art Bible 2.0 提供跨题材母风格思想。

文档中的建议、示例、签字流程和外部参考链接属于参考材料。用户此次要求是阅读理解并重新设计，没有要求申请主美签字、复制参考产品、上线商业化、制作全部三维源文件或联网核实其中的历史论述。本设计将相关内容转化为项目内的可执行规范，不将文档中的命令式文字当作额外授权。

| 需要消歧的内容 | 本次采用的决定 | 原因 |
|---|---|---|
| 粘贴稿以四世界为例，JSON 为五世界独立型 | 皇家、科幻、现代、古代、童话五世界 | JSON 与两份新套件明确给出五世界结构 |
| Toy 的含义 | 厚实体积与可触摸感；石头、布料、金属保持各自材质 | 避免全项目变成同一种塑胶 |
| 原文 48dp 热区、12dp caption | 热区 ≥48，主要动作56；游戏正文18、关键目标28以上，12仅限非关键信息 | 输入训练需要更高的阅读优先级 |
| 色值与85分评分 | 用作探索基线，须在原型与实机上验证 | 输入 JSON 标记为 proposal-for-art-tests |
| 五世界与十课程的关系 | 课程决定内容，玩法决定规则，世界决定表现 | 玩家不会为了练 F/J 被迫接受高阶词汇 |
| 参考作品 | 提取形体、剪影、材质概括、反馈原则，建立自己的符号 | 项目长期视觉身份需独立 |

继承链：Core → Theme → Gameplay Adapter → Component → Screen。世界不覆盖危险、正确、禁用等语义；页面不自行发明新的确认或返回规则。

## 2. 产品身份

**名称：键境 · Keybound。定位：用键盘探索五个微缩世界的学习冒险游戏集合。**

儿童友好、英勇幽默、精致厚实、清晰可读。品牌主符号是“两枚相向键帽构成的开口菱形”，暗示左右手配合与前进方向；避免皇冠式身份标识。品牌徽记是界面向量组件，角色与场景是独立美术资产。

大厅以世界入口和清楚的学习目标建立期待。训练优先鼓励准确与回位；挑战提供速度、反应和策略压力。失败表达为“这次守到第3波，下次先处理疾行兽”，不使用羞辱式评价、连续失败惩罚或儿童付费压力。

## 3. 母风格：Heroic Toy-Stylized

### 3.1 形体、比例、剪影

- 一个主形体，2–4个功能次形体；65/25/10仅是视觉密度启发，不是面积硬配额。
- 人形探索区间2.5–4.5头身；重装低重心、宽肩短腿，速度型前倾，支援型开放向上。只夸张1–2处功能特征。
- 主体采用厚实圆角几何与明确倒角；危险方向可尖锐，边缘不使用细碎锯齿。
- 主形、功能件、装饰依次递减。游戏中同一敌人不能靠腰带扣与纹身区分职业。
- 48/96/192px 剪影检查是补充；最终以怪物在实际战场中的显示尺寸判断。普通怪物预计48–72逻辑单位，Boss96–144，需经实机修正。

### 3.2 色彩与明度

大面积背景为低至中饱和；角色、可操作件、目标词构成少量高对比焦点。环境、角色、UI三个层级不得同时满饱和。背景细节越靠近词牌越少。

全局语义：友方蓝、敌方红、正确绿、预警金、危险红、特殊紫、禁用灰。每种语义另有文字或形状：正确✓、错误×、危险三角、锁定双角括号、选中菱形标记。红色敌人不意味着红色按钮可攻击。

色值定义见 `tokens.resolved.json`。主题 primary 不自动承担白字按钮底色：主题黄铜、浅绿等需深色文字；正文文字与实色底目标对比≥4.5:1，重要图标/焦点边界≥3:1。动效、透明叠色和复杂背景必须单独检查，不能只验HEX。

### 3.3 材质与光照

| 材质 | 表现 | 应剔除 |
|---|---|---|
| 石 | 2–3层宽色块、大倒角、少量块状缺口 | 摄影石纹与密集裂隙 |
| 木 | 温暖大色面、少数宽木纹、厚接缝 | 真实纤维与脏污颗粒 |
| 金属 | 简洁宽高光、暖冷反射分区 | 镜面噪点与密集铆钉 |
| 布 | 宽褶皱、厚织物边缘 | 真实织物细纹 |
| 釉面 | 轻微弧面、一个主要高光 | 每个物体都糖果化 |
| 植物 | 成组大叶、体积明确 | 满屏高频草叶 |
| 能量/玻璃 | 有边界的发光、内芯可见 | 大面积泛白遮字 |

同一场景主光左上方，柔和补光，脚底接触阴影。2D预渲染精灵同样遵守光向；移动时不因朝向翻转而随意翻转高光。宣传图可增加轮廓光，战斗图以识别为先。

### 3.4 空间与镜头

每个场景分核心行动区、功能区、外围叙事区。可玩区低干扰，路口和建筑中等复杂，边缘讲世界故事。微缩舞台感来自体积和空间层级，不强制所有玩法使用同一镜头。

俯视城防：建议浅俯视正交；横版格斗：固定侧视；气球/泡泡：正视；赛车：固定俯视；指法：面向屏幕的中性教学台。贴图中的道路不自动代表寻路或碰撞，二者由玩法数据定义。

## 6. 实体 UI 系统

### 6.1 视觉骨架

外层结构框架 → 中层阅读面 → 内层控件。大型面板使用白色或很浅的主题底、1dp边和低不透明度柔影；主题身份通过轻微色温和入口插画表达。正文有独立阅读面，普通面板不加金属扣角与厚实底板。

主按钮用浅杏色与深棕字，默认56高、18圆角、2dp轻微深度；次按钮用白底与深色字，第三操作使用轻边框。焦点是清晰蓝色外环，选择是内部底色、边框与菱标；两者可同时存在。悬停不是唯一的信息入口。

### 6.2 组件目录

| 组件 | 最小信息 | 状态与规则 |
|---|---|---|
| WorldPortal 世界入口 | 世界名、主题剪影、玩法数量 | 当前、聚焦、未选；世界不伪装成课程锁 |
| LessonNode 课程节点 | 阶段号、目标键、训练目的、掌握状态 | 推荐/当前/已掌握/开放；全部可访问 |
| GameTile 玩法入口 | 主题物体、名称、训练能力、压力、课程来源 | 一张入口一个主动作；不用卡牌稀有度表达学习等级 |
| Primary/Secondary/QuietButton | 动词、快捷键、可用原因 | 默认/按下/聚焦/选中/禁用/加载，状态可组合 |
| WordPlate | 原文、已输入、当前字符、紧迫度 | 原文深墨；前缀✓绿色；当前下划线；错误×提示 |
| ThreatPlate | 兵种小图标、词、血量、蓄力 | 碰撞避让；标签层高于特效；屏边钳制 |
| ResourceSlot | 图标、名称、数值 | 金币和学习XP分开；不做付费货币暗示 |
| CoachDock | 下个键、左右手指、基准键、虚拟键盘 | 完整/紧凑/隐藏；展开时主动暂停当前局 |
| Pause/Result/ImportModal | 标题、内容、一个主动作、安全返回 | 焦点闭环；返回恢复原入口；导入默认焦点取消 |
| Toast | 状态词、简短原因 | 非模态；不夺焦点；最多两条，合并重复奖励 |
| SettingsRow | 设置名、当前值、帮助 | 声音、减少动态、文字尺寸、指法教练、存档 |

### 6.3 文本、目标与无障碍

中文标题采用粗字重、正文易读无衬线；输入目标用清楚区分 `I/l/1`、`O/0` 的拉丁字形。不得在图片中烘焙目标词、UI文案、数值。字体分包覆盖课程标点和新增中文；不得因字体回退丢失Shift符号。

字号项目覆盖：标题40/32、分组24、正文18、提示16、目标32–48、紧凑标签14。可缩放到125%/150%，面板重排不裁字。正确、错误、选中、警报均有非颜色线索。

## 7. 动效与打击感

按下100ms降低正面与厚度，松开160ms回位；面板进入260ms；奖励560ms可跳过。焦点迁移不移动其他按钮。按键提示用1次轻压，不持续闪烁。

| 反馈 | 设计起点 | 阅读保护 |
|---|---|---|
| 正确键 | 80–120ms 小高光、前缀即时更新 | 输入判定先发生，动画不锁输入 |
| 错误键 | 160ms ×与当前字符提示 | 不用全屏红闪；保留当前进度 |
| 普通命中 | 80ms预备、120ms冲击、240ms消散 | 爆点在角色身上，不在词牌上 |
| 重击/Boss | 100ms预备、40ms视觉停顿、300ms恢复 | 只停角色表现，输入时间与统计不被改写 |
| 奖励 | 一次弹起+数值合并 | 不挡下一局主按钮 |

减少动态模式关闭镜头震动、飞入、视差、弹性和停顿，保留静态高光、形状提示、数字变化。屏幕层HUD与目标文字不参与镜头震动。音效需要视觉冗余，静音仍可完成所有游戏。

## 8. 技术交付边界

Godot 2D / Compatibility，网页目标继续使用单线程方案。Core组件使用Control/Theme/StyleBoxTexture、MarginContainer、BoxContainer和GridContainer；背景、角色、VFX独立节点。九宫格图片只含材质边框，文字与按压状态由代码控制。

1280×800作为桌面排布基线；1440×900保持同构，宽屏增加场景视野或留氛围边，不拉长怪物与按钮。1024×768收紧为两列入口并缩短侧教练；更窄宽度将教练改为暂停抽屉，菜单可纵向滚动。网页无实体键盘时说明需要键盘；不承诺手机触屏打字等价体验。

颜色、间距、厚度、动效从resolved tokens读取；HUD通过状态变化信号更新；ScreenStack管理输入权、暂停与焦点恢复。世界切换不修改存档课程ID与已有成绩键。

完整页面与键盘状态机见 `INTERACTION_SPEC.md`，资产生产、迁移与验收见 `PRODUCTION_PLAN.md`。原型从 `index.html` 打开，可选五世界、课程、十款玩法、挑战、指法、城堡建设、结算与组件状态。
